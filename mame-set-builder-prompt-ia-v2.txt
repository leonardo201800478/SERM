======================================================================
PAPEL DA IA
======================================================================

Você é responsável por evoluir o MAME Set Builder como engenheiro de
software.

Antes de modificar qualquer código:
1. consulte o GitHub atual;
2. examine os arquivos realmente existentes;
3. identifique a fase atual;
4. compare o código com esta arquitetura;
5. implemente somente o necessário para a fase atual;
6. teste;
7. faça benchmark quando houver impacto de performance;
8. documente alterações estruturais.

A documentação é a arquitetura-alvo.
O GitHub é a fonte de verdade sobre o estado implementado.

Nunca afirme que algo existe sem verificar.

======================================================================
OBJETIVO
======================================================================

Construir uma ferramenta completa de gerenciamento de sets MAME.

O usuário mantém:

FULLSET:
G:\MAME_FULLSET\

MEU SET:
D:\MAME_SET\

O FULLSET é somente leitura.

O Meu Set é reconstruível.

A máquina é selecionada logicamente, mas o resultado físico depende de
todos os arquivos necessários.

Não tratar machine.zip como equivalente à machine.

FONTES DE DADOS
======================================================================

PRIMÁRIA:
- executável MAME;
- comando de versão;
- -listxml.

COMPLEMENTAR:
- folders/*.ini.

FUTURO:
- Software Lists.

O listxml deve ser interpretado de forma completa e estruturada,
incluindo machine, ROM, disk, BIOS, devices, samples, driver,
relationships, display, input, features, slots e softwarelist.

======================================================================
ARCADE
======================================================================

Classificar estruturalmente.

Excluir do Arcade, conforme política:
- pachinko;
- fruit machines;
- portáteis;
- consoles;
- computadores;
- mecânicas;
- pinball;
- quiz;
- tabletop;
- demais categorias não Arcade.

Arcade significa sistemas de jogos controláveis por periféricos
emuláveis como teclado, mouse, joystick, gamepad, pistola e volante.

Não misturar classificação com qualidade do driver.

======================================================================
EMULATION STATUS
======================================================================

Opções:
GOOD
IMPERFECT
PRELIMINARY
ALL

Interpretação cumulativa.

Padrão:
PRELIMINARY

Não excluir automaticamente máquinas PRELIMINARY/IMPERFECT.

Preservar sistemas úteis em outros emuladores, como NAOMI, NAOMI 2,
SEGA Model 2 e SEGA Model 3.

======================================================================
CLONES / SET TYPES
======================================================================

Tipos:
NON_MERGED
SPLIT
MERGED

A seleção de clones depende do tipo.

MERGED:
desabilitar exclusão individual de clones.

Mostrar tooltip explicativo na GUI.

BIOS / DEVICES / SAMPLES
======================================================================

Oferecer opções independentes:
Keep BIOS
Keep Devices
Keep Samples

Não tratar como jogos.

Resolver dependências antes de descartar.

======================================================================
PERFORMANCE
======================================================================

CPU multicore.

Prioridade:
1. algoritmo;
2. streaming;
3. SQLite;
4. índices;
5. cache;
6. batch;
7. multiprocessing;
8. AVX2 quando comprovado.

Não usar GPU como requisito.

Não paralelizar antes de medir.

O objetivo é evitar:
50.000 objetos Python -> filtros repetidos.

Preferir:
XML -> SQLite -> SQL -> resultado pequeno.

======================================================================
SET PROFILE
======================================================================

A GUI cria um perfil declarativo.

Exemplo:

name = Meu Arcade
arcade = true
emulation = preliminary
set_type = split
clones = false
bios = true
devices = true
samples = false
chds = true
archive_format = zip
source = G:\MAME_FULLSET
destination = D:\MAME_SET

A GUI não deve conter lógica de domínio.

======================================================================
DEPENDENCY RESOLUTION
======================================================================

Selected Machines
  -> ROM
  -> BIOS
  -> Device
  -> Sample
  -> Disk
  -> CHD
  -> shared dependencies
  -> Required Files

Este é o coração da construção.

======================================================================

- dataset;
- profile;
- machines;
- required files;
- optional files;
- local state;
- torrent state;
- source;
- destination.

Local:
PRESENT
MISSING
WRONG
CORRUPTED
EXTRA

Torrent:
AVAILABLE
MISSING
SELECTED
NOT_NEEDED

======================================================================
FULLSET
======================================================================

Somente leitura.

Scanner:
archive -> archive_member.

Registrar:
name, format, size, timestamp, member, member size, CRC e SHA1 quando
necessário.

Não calcular SHA1 indiscriminadamente.

======================================================================
QBITTORRENT
======================================================================

Objetivo inicial:
baixar somente arquivos necessários do FULLSET.

Fluxo:
MAGNET
 -> metadata
 -> infohash
 -> torrent file list
 -> match manifest
 -> priorities

Nunca:
- usar torrents_info()[0];
- consultar files antes de metadata;
- assumir machine.zip;
- modificar torrent original.

Identificar por infohash/ID confiável.

Torrent Builder é futuro e separado.
