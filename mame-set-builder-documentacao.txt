============================================================
1. VISÃO GERAL
============================================================

O MAME Set Builder é um projeto destinado inicialmente a selecionar e construir conjuntos personalizados de ROMs MAME.

A visão final é transformá-lo em uma ferramenta especializada de gerenciamento de ROMs MAME, capaz de:

- interpretar profundamente o listxml.xml do MAME;
- classificar máquinas;
- filtrar máquinas por regras configuráveis;
- preservar sistemas importantes mesmo quando o MAME informa suporte imperfeito;
- resolver dependências entre machines, ROMs, BIOS, samples, discos e CHDs;
- gerar DATs;
- verificar ROMs existentes;
- identificar ROMs faltantes;
- integrar com qBittorrent;
- usar magnets de torrents full set;
- selecionar somente os arquivos necessários dentro de um torrent;
- futuramente reconstruir sets personalizados;
- eventualmente evoluir para um ROM Manager completo.

A ferramenta não deve assumir que a qualidade de emulação do MAME determina se uma máquina deve ser mantida.

============================================================
2. PRINCÍPIO FUNDAMENTAL
============================================================

O projeto deve entender a estrutura do MAME, e não apenas procurar arquivos com nomes correspondentes às machines.

O modelo fundamental é:

Machine
  ↓
Dependencies
  ↓
Required Files
  ↓
SetManifest

A partir do SetManifest são derivados:

SetManifest
  ├── DAT
  ├── Local Verification
  ├── Missing Files
  ├── Torrent Matching
  ├── qBittorrent Download
  └── Future Rebuild

Isso evita duplicação de lógica.

============================================================
3. FONTES DE DADOS
============================================================

Fonte principal:

MAME listxml.xml

Documentação:
https://docs.mamedev.org/commandline/commandline-all.html#mame-commandline-listxml

O listxml contém informações muito mais completas do que simplesmente nome e descrição.

Também deve ser consultada a documentação de Software Lists:

https://docs.mamedev.org/contributing/softlist.html

Fontes complementares podem existir, mas somente devem ser usadas quando a informação não puder ser obtida adequadamente do listxml.

============================================================
6. SISTEMAS ESPECIAIS
============================================================

O projeto deve preservar sistemas como:

Sega NAOMI
Sega NAOMI 2
Sega Model 2
Sega Model 3
Neo Geo

mesmo que o suporte MAME seja imperfect ou preliminary.

Motivo:

A finalidade do set é preservar software e hardware emulado, e não exclusivamente software considerado plenamente funcional pelo MAME.

Outros emuladores podem executar esses sistemas melhor.

Portanto o sistema deve permitir regras explícitas de preservação.

============================================================
8. INIs
============================================================

A implementação atual possui dependência de arquivos INI.

Eles não devem ser removidos imediatamente.

Primeiro deve ser feito um inventário:

- qual arquivo INI é usado;
- qual informação contém;
- quais filtros dependem dele;
- se a informação já está no listxml;
- se o dado é realmente necessário.

Se o listxml já possuir a informação, a dependência deve ser eliminada gradualmente.

Se o INI possuir uma classificação útil que não exista no listxml, ele pode permanecer como fonte complementar.

============================================================
9. PERFORMANCE
============================================================

A implementação atual tende a materializar máquinas em objetos Python e aplicar filtros posteriormente.

Isso gera:

- overhead de objetos;
- uso de memória;
- processamento desnecessário;
- I/O;
- filtragens repetidas.

Estratégia:

1. parser eficiente;
2. processamento streaming;
3. SQLite;
4. índices;
5. consultas eficientes;
6. evitar materialização completa;
7. cache;
8. profiling;
9. paralelismo apenas quando comprovado;
10. GPU apenas para operações realmente apropriadas.

O uso elevado de CPU não é um objetivo por si só.

O objetivo é reduzir o tempo total.

GPU não deve ser utilizada artificialmente.

============================================================
11. DEPENDENCY RESOLVER
============================================================

Esse é um dos componentes centrais.

Não assumir:

machine = name.zip

Uma machine pode depender de:

- parent;
- ROMs merged;
- BIOS;
- samples;
- disks;
- CHDs;
- devices;
- outros componentes.

O Dependency Resolver deve transformar:

Selected Machines

em:

Required Files.

Cada RequiredFile deve conter, quando aplicável:

path
name
size
crc
sha1
machine
type
dependency source

============================================================
12. SETMANIFEST
============================================================

SetManifest é a representação central do set.

Estrutura conceitual:

SetManifest
├── metadata
│   ├── MAME version
│   ├── build
│   ├── listxml hash
│   ├── generation date
│   └── profile
├── selected machines
├── excluded machines
├── required ROMs
├── required disks
├── present files
├── missing files
└── torrent information

Todos os módulos posteriores devem consumir o SetManifest.

============================================================
13. DAT
============================================================

O DAT deve ser derivado do SetManifest.

Fluxo:

Selection
  ↓
Dependency Resolver
  ↓
SetManifest
  ↓
DAT Exporter

O DAT não deve ser construído apenas com nomes de machines.

Ele deve representar o conjunto efetivamente necessário.

============================================================
14. SCANNER LOCAL
============================================================

O scanner local compara:

RequiredFiles

com:

filesystem.

Resultados possíveis:

PRESENT
MISSING
WRONG
EXTRA

Comparação:

1. nome/caminho;
2. tamanho;
3. CRC;
4. SHA1.

CHDs/discos devem usar seus identificadores próprios.

============================================================
15. QBITTORRENT
============================================================

Objetivo:

Utilizar um magnet de um full set MAME compatível e baixar somente arquivos necessários.

Fluxo:

MAGNET
  ↓
qBittorrent
  ↓
metadata
  ↓
torrent contents
  ↓
match
  ↓
file priority
  ↓
download

Não é necessário baixar manualmente o arquivo .torrent.

É necessário aguardar a obtenção dos metadados antes de conhecer a árvore completa de arquivos.

Nunca assumir que o primeiro torrent retornado pela API é o torrent recém-adicionado.

Identificar o torrent de forma robusta.

============================================================
16. MATCHING DO TORRENT
============================================================

RequiredFile deve ser comparado com TorrentFile.

TorrentFile:

index
path
size
priority

RequiredFile:

path
size
crc
sha1

Estados:

MATCHED
MISSING
UNMATCHED
AMBIGUOUS

O sistema deve informar quando o torrent não corresponde à versão esperada.

============================================================
17. RECONSTRUÇÃO DE TORRENT
============================================================

Não é a estratégia principal.

Criar outro torrent com subset dos arquivos gera outro infohash.

Isso quebra a equivalência com o torrent original.

A solução preferencial é:

Torrent original
  ↓
seleção de arquivos
  ↓
prioridade individual
  ↓
download seletivo

============================================================
19. ROMVAULT
============================================================

RomVault deve ser tratado como ferramenta complementar.

O MAME Set Builder deve produzir DATs compatíveis e permitir que ferramentas externas façam gerenciamento adicional.

A meta inicial não é substituir RomVault.

A meta futura é incorporar funcionalidades semelhantes ao gerenciamento de ROMs MAME.

============================================================
26. REGRAS IMPORTANTES
============================================================

- Não reescrever o projeto inteiro.
- Não remover funcionalidades funcionando sem justificativa.
- Não remover INIs sem auditoria.
- Não tratar MAME preliminary como lixo automaticamente.
- Não usar nome da machine como equivalente universal de arquivo.
- Não gerar DAT sem resolver dependências.
- Não baixar torrent inteiro quando apenas parte é necessária.
- Não reconstruir torrent como solução principal.
- Não usar GPU sem benefício mensurável.
- Não adicionar threading sem benchmark.
- Não duplicar regras na GUI.
- Não duplicar lógica entre DAT, torrent e scanner.
- SetManifest deve centralizar o estado do set.
- Consultar documentação oficial atualizada.
- Sempre examinar o código atual do GitHub antes de modificar.

============================================================

MAME
  ↓
Machines
  ↓
Relationships
  ↓
ROMs
  ↓
BIOS
  ↓
Samples
  ↓
Disks/CHDs
  ↓
Dependencies
  ↓
SetManifest
  ↓
DAT
  ↓
Local Set
  ↓
Torrent
  ↓
qBittorrent
  ↓
Download seletivo

e futuramente:

Set
  ↓
Rebuild
  ↓
Custom Set

O projeto deve ser capaz de preservar sistemas importantes para o usuário mesmo quando o MAME não seja o melhor emulador para eles.

O objetivo não é simplesmente construir "um filtro de ROMs".

O objetivo é construir um sistema de gerenciamento de conjuntos MAME baseado na estrutura real dos dados do MAME.
